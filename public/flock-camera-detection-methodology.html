Detection Methodology — Confidence Tiers and Evidence Chains

FlockWatch Compass uses a deterministic, auditable confidence model. The LLM explains evidence — it never decides whether a camera exists.

The Core Principle

The biggest problem with community surveillance maps is false positives becoming permanent facts. A single OUI match or SSID pattern is not definitive — Flock's wireless behavior changes, and other devices can share similar signatures. FlockWatch Compass addresses this by requiring multiple independent indicators and separating "possible" from "confirmed."

4-Tier Confidence Model

Every detection is assigned a confidence tier by deterministic code — not by an AI. The tier is based on the number and independence of evidence sources:

TierRequirementsMeaning
Unconfirmed One weak indicator (e.g., single OUI match) May be a false positive. Insufficient for action.
Probable Multiple independent passive indicators, or repeated observations across time Warrants further investigation. Collect more data.
Supported Passive detection + independent public evidence (FCC, municipal, news) Strong evidence. Consider field verification.
Machine-supported Repeated automated observations across multiple days + multiple RF modes + public corroboration Highest automated confidence. No manual verification required.

Evidence Chain Pattern

Every detection lead follows an auditable evidence chain adapted from Project Compass's decision-support framework:

Evidence → Interpretation → Recommendation → Action → Owner → Dependency → Success criterion

This ensures every finding is traceable. You can see exactly what evidence supported a detection, how it was interpreted, what was recommended, and what success looks like.

Detection Methods

FlockWatch Compass uses multiple detection methods, each contributing to the evidence:

  • OUI prefix matching — MAC address vendor prefixes compared against known Flock Safety OUIs
  • SSID pattern matching — Wi-Fi network names checked against Flock naming patterns
  • BLE service UUIDs — Bluetooth service identifiers compared against known Flock UUIDs
  • BLE manufacturer ID — Bluetooth SIG manufacturer IDs for Flock's module suppliers
  • Wi-Fi probe/IE fingerprinting — Information element sequences in probe requests create device-specific fingerprints
  • RF spectral fingerprinting — SDR I/Q captures compared against reference templates using cosine similarity
  • Burst timing analysis — Transmission interval patterns (regular beacons vs. irregular traffic)
  • Cross-source corroboration — Multiple source devices detecting the same location

Why Not Let the AI Decide?

LLMs can hallucinate. They can pattern-match on insufficient evidence and confidently assert things that are wrong. In surveillance mapping, a false positive can mislead communities, waste resources, and erode trust. FlockWatch Compass keeps the AI in an explanatory role — it can summarize evidence, suggest next steps, and write reports — but the confidence tier is computed by deterministic code that anyone can inspect. No manual verification is required to reach the highest automated tier (machine-supported): repeated observations across multiple days using multiple RF modes, plus independent public corroboration, is sufficient.

Observation Schema

Each observation from the detector is a structured record:

Observation
├── GPS coordinates + accuracy
├── Timestamp (ISO 8601)
├── RSSI (signal strength)
├── Radio type (Wi-Fi / BLE / sub-GHz / SDR)
├── MAC address + OUI prefix
├── SSID (if Wi-Fi)
├── BLE name, service UUIDs, manufacturer ID
├── Probe/IE fingerprint (if available)
├── RF fingerprint (PSD, bursts, timing)
├── Detection methods triggered
├── Source device (ESP32, Flipper, SDR, WiGLE)
└── Raw payload hash (SHA-256 for integrity)
